# LangGraph Recommendation Workflow V1 — Review

## Final assessment

**LANGGRAPH RECOMMENDATION WORKFLOW = READY_FOR_PROJECT_REVIEW**

The FastAPI candidate-scoped retrieval endpoint now executes a compiled LangGraph. Spring hard filters, candidate ownership, final ranking, Venue deduplication and max-three selection remain unchanged. Both the semantic Compose Browser E2E and isolated AI-unavailable fallback Browser E2E passed.

## Existing flow and graph boundary

Spring still calls the existing intent endpoint, applies all hard filters, then sends the filtered IDs to the existing semantic retrieval endpoint. The graph is inside FastAPI behind that retrieval route; it invokes the existing deterministic intent analyzer and passes its result into the existing retrieval service. This keeps the request/response JSON contract and avoids another intent computation inside retrieval. The separate post-ranking explanation endpoint is unchanged.

Nodes are `prepare`, `intent_analysis`, `semantic_skip`, `semantic_retrieval`, `retrieval_evaluation`, `bounded_retry`, `fallback`, and `finalize`. Conditional routes select skip versus retrieval, then success versus retry versus fallback. The graph compiles once per FastAPI process. Async `ainvoke` is used by the async route.

| Outcome | Graph behavior | External behavior |
| --- | --- | --- |
| UNKNOWN/generic intent | Skip retrieval and finalize | Existing empty result; no embedding/Qdrant |
| Retrieval success | Finalize semantic result | Existing response schema |
| Empty Qdrant result | No retry; empty fallback | HTTP 200 with empty candidates |
| Transient transport or HTTP 500/502/503/504 | Retry once with unchanged query/candidate IDs | Success or sanitized HTTP 503 after exhaustion |
| HTTP 429/4xx, malformed response, invalid scope payload | No retry; failure fallback | Sanitized HTTP 503; Spring configured fallback remains authoritative |

The only retry owner is now the graph. Before this work urllib had no retry and Spring `AI_MAX_ATTEMPTS` defaulted to one. Retry preserves the same semantic query and candidate tuple; no rewrite or scope broadening occurs.

## Limitations and handoff

The existing deterministic intent schema is still intentionally small; this work did not add intent classification, query rewrite, generative AI, or a LangGraph debug field to Spring's response. Trace is operational log observability, not a persisted workflow history. Real provider retry behavior is covered by classification/unit tests; the Compose tests exercise success and whole-AI-unavailable Spring fallback, while graph-internal retry routing uses deterministic service doubles.

Data Pipeline remains **EXPERIMENTAL / FROZEN**: no Generator, Atomicizer, Verifier, embedding, indexing or Qdrant writes ran. The AI feature is still opt-in and default-off. This is a project-review handoff, not authorization to expand profiles, change production flags, or deploy.
